# UX Audit: Career Seek

**Date**: 2026-04-30  
**Scenario**: "Find the best job to act on today, understand why it matters, prepare application assets, and manage follow-up without losing confidence."  
**Persona**: "A time-poor job seeker with moderate tech comfort, using the app between other responsibilities. They care about speed, trust, and knowing exactly what to do next."  
**Browser**: Playwright MCP  
**Viewport**: Desktop 1440x1000 and mobile 390x844  

## Summary

Career Seek now has a distinctive, polished, and task-oriented interface. The redesigned visual system gives the app a clear point of view, and the Today dashboard is strong at answering "what should I do next?"

The biggest UX risks are not visual. They are trust and resilience issues: `/notifications` is currently broken, the pipeline add-job modal has keyboard accessibility gaps, several mobile destinations are hidden, and some AI/search outputs do not connect directly to visible next actions. Overall, the product feels close to useful daily software, but it needs a pass on mobile information architecture, accessibility, and recovery paths before it feels dependable.

## Findings

### Critical

- **Notifications route is broken**: Opening `/notifications` shows the shared error page with `Queue name cannot contain :`. The route also produced repeated console errors during the audit.
  - *Where*: `/notifications`
  - *Screenshot*: [ux-audit-notifications-desktop.png](../ux-audit-notifications-desktop.png)
  - *Evidence*: [ux-audit-notifications-console-errors.txt](../ux-audit-notifications-console-errors.txt)
  - *Impact*: A user cannot review reminders or trust the app's follow-up system.
  - *Fix*: Patch the queue/reminder initialization path so queue names avoid invalid characters, then add a smoke test for `/notifications`.

### High

- **Mobile nav hides major sections**: The mobile bottom nav exposes Today, Discover, Pipeline, AI Coach, and More. "More" links directly to `/settings`; it does not reveal Saved, Applied, Documents, Notifications, or Analytics.
  - *Where*: mobile global navigation
  - *Screenshot*: [ux-audit-settings-mobile.png](../ux-audit-settings-mobile.png)
  - *Impact*: A first-time mobile user may never discover generated documents, saved jobs, application history, analytics, or reminders.
  - *Fix*: Make More open a menu/sheet with all secondary destinations, or add a real mobile app menu in the header.

- **Pipeline add-job modal is not keyboard-resilient**: The Track Job modal blocks background clicks, which is good, but Escape did not close it and repeated Tab navigation allowed focus to leave the dialog.
  - *Where*: `/pipeline`, Track Job modal
  - *Screenshot*: [ux-audit-pipeline-desktop.png](../ux-audit-pipeline-desktop.png)
  - *Impact*: Keyboard and assistive-technology users can get disoriented or stuck.
  - *Fix*: Add dialog focus trapping, restore focus to the opener on close, and support Escape-to-close with the same discard guard used by Cancel.

- **Icon-only actions lack accessible names**: The pipeline detail and applied-history external-link actions appear as icon-only controls. In the accessibility snapshot, at least one applied-page link had no readable name.
  - *Where*: `/pipeline/[id]`, `/applied`
  - *Screenshots*: [ux-audit-pipeline-detail.png](../ux-audit-pipeline-detail.png), [ux-audit-applied-desktop.png](../ux-audit-applied-desktop.png)
  - *Impact*: Screen-reader users do not know what the action does; sighted users also have less confidence.
  - *Fix*: Add `aria-label`, `title`, visible tooltip text, and a minimum 44 px target for icon-only links.

- **Dashboard AI search answer is not actionable enough**: Searching the ranked queue returns a narrative answer like "I found 30 ranked queue matches..." while the visible queue can show a different filtered subset, such as `Ranked queue (5)` or `Ranked queue (0)`.
  - *Where*: Today dashboard search
  - *Screenshot*: [ux-audit-dashboard-desktop-styled.png](../ux-audit-dashboard-desktop-styled.png)
  - *Impact*: The user gets insight but not a clear next click. It creates a gap between AI answer and visible work queue.
  - *Fix*: Link each named result to its card/detail page, highlight matching cards, and show whether filters are currently hiding matches.

### Medium

- **Discover search and filter state does not persist on refresh**: After searching Discover, refreshing or reloading the page resets query and filter state.
  - *Where*: `/discover`
  - *Screenshot*: [ux-audit-discover-desktop.png](../ux-audit-discover-desktop.png)
  - *Impact*: Users doing iterative job review lose context.
  - *Fix*: Store query and filters in URL search params, or persist the last search locally with a visible reset control.

- **Many mobile controls are below recommended touch size**: Several visible buttons and chips measured around 40 px high, including job actions and filters.
  - *Where*: mobile Today/dashboard
  - *Screenshot*: [ux-audit-dashboard-mobile.png](../ux-audit-dashboard-mobile.png)
  - *Impact*: Controls are usable, but less forgiving for thumbs and accessibility.
  - *Fix*: Set a 44 px minimum height for touch controls on mobile.

- **Pipeline board horizontal scrolling is easy to miss**: The board layout is appropriate for pipeline work, but on desktop the right columns can be clipped and the scroll affordance sits low on the page.
  - *Where*: `/pipeline`, board view
  - *Screenshot*: [ux-audit-pipeline-desktop.png](../ux-audit-pipeline-desktop.png)
  - *Impact*: A user may believe later statuses are missing.
  - *Fix*: Add sticky column-summary tabs, visible edge fade, or a "scroll for later stages" affordance.

- **Document-to-job relationship is too indirect**: The Documents page makes generated assets easy to see, but "View jobs" points broadly to Discover instead of the exact source job or application context.
  - *Where*: `/documents`
  - *Screenshot*: [ux-audit-documents-desktop.png](../ux-audit-documents-desktop.png)
  - *Impact*: The user must reconstruct why a resume, cover letter, or outreach note exists.
  - *Fix*: Link each asset to the related job detail or pipeline record, and label the action "Open source job" or "Open application".

- **Scores need stronger explanation**: Some top-level job cards surface low-looking match or confidence scores while still presenting the job as the top next action.
  - *Where*: Today and Discover job cards
  - *Impact*: A job seeker may wonder whether the app is recommending a weak job.
  - *Fix*: Add plain-language score interpretation, for example "Best available match today because..." and show the strongest/weakest score drivers.

- **Analytics empty state is passive**: The page says no active insights exist and offers "Refresh insights," but the user must decide whether refreshing is safe, slow, or useful.
  - *Where*: `/analytics`
  - *Screenshot*: [ux-audit-analytics-desktop.png](../ux-audit-analytics-desktop.png)
  - *Impact*: Insight generation feels optional and uncertain.
  - *Fix*: Add microcopy around what refresh does, whether it changes data, and when it was last run.

### Low

- **Some generated-document labels read like internal filenames**: Labels such as version-style asset names are precise but not always human.
  - *Where*: `/documents`
  - *Fix*: Use user-facing labels first, with filename/version as metadata.

- **Dense chips and prompts in Coach require extra scanning**: The Coach page has strong evidence grounding, but the prompt/chip region can feel busy.
  - *Where*: `/coach`
  - *Fix*: Group prompts by intent, such as "resume", "job fit", and "interview".

- **The local-data badge is useful but visually prominent**: It reassures technical users, but may distract non-technical users from the main task.
  - *Where*: global header
  - *Fix*: Keep it, but consider moving exact path details into Settings while showing a simpler "Local data" status in the header.

## Emotional Friction

- **"Can I trust reminders?"** The Notifications page fails completely. For a job seeker relying on follow-up timing, this creates immediate doubt about the whole workflow.

- **"Where did my mobile pages go?"** On mobile, a user can see the main work loop but cannot discover supporting sections like Documents or Analytics from the bottom nav.

- **"What will happen if I change status?"** Pipeline status controls are efficient, but immediate dropdown status changes can feel risky without undo or visible confirmation.

- **"What do I do with this AI answer?"** The dashboard search answer sounds intelligent but does not move the user directly into an action.

- **"Is this job actually good?"** Low-looking scores near top recommendations need clearer framing so the user does not distrust the ranking logic.

## What Works Well

- The Today dashboard is the best part of the app. It quickly tells the user who they are, what is queued, and which job deserves attention.
- The design system feels cohesive and memorable without turning into a marketing page.
- Empty states are generally helpful, especially Saved and Discover no-results states.
- Coach answers feel more trustworthy because they include confidence and source grounding.
- Pipeline board/list switching supports both visual planning and dense review.
- Settings groups AI provider, resume profile, search goals, and backups in a way that makes operational sense.
- The app avoids horizontal overflow on mobile in the tested viewport.

## Recommendations

1. **Fix `/notifications` first.** It is a top-level navigation item and currently blocks reminder review entirely.
2. **Repair modal and icon accessibility.** Add dialog focus trapping, Escape behavior, focus return, labels/tooltips for icon-only actions, and 44 px minimum targets.
3. **Make mobile More a real menu.** Include Saved, Applied, Documents, Notifications, Analytics, and Settings.
4. **Connect AI/search answers to actions.** Link named matches, highlight filtered results, and explain when filters hide matches.
5. **Persist Discover state.** Put query and filters in URL params so refresh/back preserves the user's work.
6. **Tighten the recommendation story.** Explain why a top job is recommended even when numeric scores look modest.
7. **Make generated documents job-aware.** Link each document asset back to its exact job/application context.

## Audit Notes

- I did not submit destructive or externally visible actions.
- I opened the Track Job modal, entered required fields for validation behavior, and canceled instead of creating a new record.
- The app had a stale dev-server asset issue before restart, but after restarting the local dev server, the styled app loaded normally. This report focuses on the active app behavior after restart.
